The 8-Puzzle 🧩

Slide numbered tiles around a 3×3 grid until they land in order. Sounds simple — but finding the shortest path to the goal is a real search problem that AI textbooks love. Let's play, peek under the hood, and build it ourselves!

😃 What exactly is the 8-Puzzle?

You have a 3×3 board with 8 numbered tiles and one empty space. You can slide any tile that's next to the empty space into it. The goal: reach a target arrangement (usually 1→8 in order) starting from a shuffled one.

Why AI folks love it: at every step you have up to 4 choices (up/down/left/right move into the blank). It's small enough to reason about, but big enough (181,440 reachable arrangements) that "just try everything" gets expensive — perfect for teaching search algorithms like BFS, A*, and Branch & Bound.

🌳 "Show me all the possibilities"

From any arrangement, the blank tile can usually move in 2–4 directions — each move branches into a new state. That branching, repeated over and over, is called the state space. Below is a real slice of it: the root state and every state reachable in 1 and 2 moves.

Notice states can even reconnect (moving right then left just undoes itself) — that's why we need a visited set, coming up next. Zoomed out, the entire 8-puzzle has 9!/2 = 181,440 reachable states — far too many to draw, which is exactly why smart search (not brute force drawing) is the answer.

🧠 The algorithm, step by step

Click a step to expand it. This is the classic A\* search (a smarter Branch & Bound) used to solve the 8-puzzle optimally.

  • Represent each board as a state (a list of 9 numbers, 0 = blank).

    e.g. [1,2,3,4,5,6,7,0,8] means the blank sits in position 7 (0-indexed).

  • Define a cost function f(n) = g(n) + h(n).

    g(n) = moves taken so far. h(n) = heuristic estimate to the goal — usually "Manhattan distance": sum of how far each tile is from its goal position.

  • Put the start state into a priority queue, ordered by lowest f(n).

    Lower f(n) = "looks more promising" — explore those first.

  • Pop the most promising state. If it's the goal — done! Return the path.

    We reconstruct the path by remembering each state's parent.

  • Otherwise, generate its neighbors (slide blank up/down/left/right).

    Skip moves that would push the blank off the board.

  • Skip any neighbor already in the visited set; push new ones into the queue with updated f(n).

    This avoids infinite loops and re-exploring the same board twice.

  • Repeat steps 4–6 until the goal pops out, or the queue empties.

    Because we always expand the lowest f(n) first, the first time we pop the goal, it's guaranteed optimal (fewest moves). If the queue empties before that happens, every reachable state has been checked and none was the goal — no solution exists from this start (A* doesn't test solvability up front, it just exhausts the search).

📦 Which data structures — and why

⛰️

Priority Queue (min-heap)

Holds all "discovered but not yet expanded" states, always giving you the one with the lowest f(n) = g+h next. Without it you'd have to scan every waiting state each time — a heap does it in O(log n) instead of O(n).

🕵️

Hash Set (visited)

Stores boards we've already expanded (as a string key like "1,2,3,4,5,6,7,0,8"). Lookup is O(1), which is what stops the search from looping forever between two boards that just undo each other's move.

🧵

Parent map / linked path

Every time we discover a new state, we record "came from this state, via this move." When we hit the goal we just walk this chain backwards — that's how we recover the actual solution, not just its length.

🔢

Plain array / tuple (the state)

The board itself is just a flat array of 9 numbers. Simple, hashable (great for the visited set), and cheap to copy when generating neighbors.

💡 Fun fact: if you swap the priority queue for a plain FIFO queue and drop the heuristic, you get plain BFS — still optimal, just slower because it explores blindly instead of "toward" the goal.

💻 Language: Python 🐍 — the complete solution

Why Python: heapq gives you a priority queue for free, and tuples hash cleanly for a visited-set. (Java works too — PriorityQueue<> + HashSet<String> — just more typing.)

🧩 AI Search Problem Formulation

Before writing any code, every AI search agent needs 4 things defined. Here's what they are for the 8-puzzle specifically:

  • State → the current arrangement of the 9 tiles
  • Actions → move the blank Up, Down, Left, or Right
  • Goal Test → does the board exactly equal the goal state?
  • Path Cost → every single move costs 1
f(n) = g(n) + h(n)
g(n) = cost so far (moves taken) h(n) = estimated cost remaining (Manhattan distance) f(n) = estimated total cost of a path through n

This is exactly why we need 5 functions: one to hold the state, one to estimate h, one to generate legal actions, one to check the goal test and rebuild the path, and one to run the whole f = g + h search loop.

STEP 1
the state

Represent the board

No class, no fuss — a puzzle is just 9 nosy numbers standing in a line.

  • Use a flat tuple of length 9 (not a 3×3 grid) — index i maps to row i//3, col i%3.
  • 0 always means "blank."
  • Tuples matter: they're hashable, so they can go straight into a Python set later (visited states).
state = (1, 2, 3, 4, 0, 6, 7, 5, 8) # shuffled start goal = (1, 2, 3, 4, 5, 6, 7, 8, 0) # solved board

STEP 2
def h(state, goal):

The heuristic — "how far off are we?"

This is your gut-feeling function: it never actually solves anything, it just guesses smartly. This is the h(n) from f = g + h.

  • Loop over every position i in state. Skip it if the tile there is 0.
  • Find where that tile should be: goal.index(tile).
  • Convert both indices into (row, col) using //3 and %3, then add up the distances.
  • 💡 Optional level-up: goal.index(tile) re-scans the goal every time. For bigger puzzles, precompute goal_pos = {tile: i for i, tile in enumerate(goal)} once, so lookup becomes instant. Not needed for 3×3, but good habit for scaling up.
def h(state, goal): total = 0 for i, tile in enumerate(state): if tile == 0: continue gi = goal.index(tile) row1, col1 = i // 3, i % 3 row2, col2 = gi // 3, gi % 3 total += abs(row1 - row2) + abs(col1 - col2) return total

STEP 3
def neighbors(state):

The move-generator

Ask the blank tile: "where CAN you go?" — up to 4 honest answers. This is the Actions piece of our problem formulation.

  • Find the blank's flat index: state.index(0), then its (row, col).
  • Try all 4 directions, skip anything that falls off the 3×3 grid.
  • Copy the state, swap the blank with that neighbor tile, and collect the new board.
def neighbors(state): results = [] i = state.index(0) row, col = i // 3, i % 3 for dr, dc in [(-1,0), (1,0), (0,-1), (0,1)]: nr, nc = row + dr, col + dc if 0 <= nr < 3 and 0 <= nc < 3: ni = nr * 3 + nc new_state = list(state) new_state[i], new_state[ni] = new_state[ni], new_state[i] results.append(tuple(new_state)) return results

STEP 4
def reconstruct(came_from, state):

The path-rebuilder

The unglamorous function nobody remembers — but without it you only know the puzzle IS solvable, not HOW.

  • Start a list with just the goal state.
  • Keep looking up came_from[state] and stepping backwards, appending each parent.
  • Reverse the list before returning it — you built it backwards!
def reconstruct(came_from, state): path = [state] while came_from[state] is not None: state = came_from[state] path.append(state) path.reverse() return path
⬇
STEP 5
def a_star(start, goal):

Wire everything together

The boss function. It doesn't know how to guess or move tiles — it just bosses steps 2 & 3 around, always chasing the lowest f = g + h.

  • Push (f, g, state, parent) for the start, where g = 0 (no moves yet) and f = g + h(start, goal).
  • Loop: heapq.heappop() always hands you the entry with the lowest f — the most "promising" state so far.
  • Check visited before recording anything — if this state was already expanded, continue immediately. Otherwise then mark it visited and record its parent (this order matters, or you can accidentally overwrite a shorter path).
  • Goal test: if state == goal → call Step 4 and return the path. 🎉
  • Else expand with Step 3. Every move costs 1, so each neighbor gets new_g = g + 1 and new_f = new_g + h(neighbor, goal), then gets pushed onto the heap.
  • If the heap runs completely empty before the goal ever pops out — no solution exists from this start (the search exhausted every reachable state, it didn't "check" solvability in advance).
import heapq def a_star(start, goal): pq = [(h(start, goal), 0, start, None)] # f, g, state, parent came_from, visited = {}, set() while pq: f, g, state, parent = heapq.heappop(pq) # lowest f first if state in visited: continue visited.add(state) came_from[state] = parent if state == goal: # goal test return reconstruct(came_from, goal) for nxt in neighbors(state): # actions if nxt not in visited: new_g = g + 1 # path cost: every move = 1 new_f = new_g + h(nxt, goal) heapq.heappush(pq, (new_f, new_g, nxt, state)) return None # heap exhausted -> no solution exists

import heapq

def h(state, goal):
    total = 0
    for i, tile in enumerate(state):
        if tile == 0:
            continue
        gi = goal.index(tile)
        row1, col1 = i // 3, i % 3
        row2, col2 = gi // 3, gi % 3
        total += abs(row1 - row2) + abs(col1 - col2)
    return total

def neighbors(state):
    results = []
    i = state.index(0)
    row, col = i // 3, i % 3
    for dr, dc in [(-1,0), (1,0), (0,-1), (0,1)]:
        nr, nc = row + dr, col + dc
        if 0 <= nr < 3 and 0 <= nc < 3:
            ni = nr * 3 + nc
            new_state = list(state)
            new_state[i], new_state[ni] = new_state[ni], new_state[i]
            results.append(tuple(new_state))
    return results

def reconstruct(came_from, state):
    path = [state]
    while came_from[state] is not None:
        state = came_from[state]
        path.append(state)
    path.reverse()
    return path

def a_star(start, goal):
    pq = [(h(start, goal), 0, start, None)]   # f, g, state, parent
    came_from, visited = {}, set()
    while pq:
        f, g, state, parent = heapq.heappop(pq)   # lowest f first
        if state in visited:
            continue
        visited.add(state)
        came_from[state] = parent
        if state == goal:                          # goal test
            return reconstruct(came_from, goal)
        for nxt in neighbors(state):                # actions
            if nxt not in visited:
                new_g = g + 1                       # path cost: every move = 1
                new_f = new_g + h(nxt, goal)
                heapq.heappush(pq, (new_f, new_g, nxt, state))
    return None  # heap exhausted -> no solution exists

# --- try it ---
start = (1, 2, 3, 4, 0, 6, 7, 5, 8)
goal  = (1, 2, 3, 4, 5, 6, 7, 8, 0)
path = a_star(start, goal)
print(f"Solved in {len(path)-1} moves")

The Water Jug Problem 🪣

You've got a 4-litre jug and a 3-litre jug, no measuring marks. Can you measure out exactly 2 litres? This tiny puzzle is a favourite for teaching state-space search because you can hold the whole problem in your head — and on one screen.

😃 What exactly is it?

Two jugs, capacities 4L and 3L. Allowed moves: fill a jug fully, empty a jug fully, or pour one jug into the other until either the source is empty or the destination is full. Starting from (0, 0), reach a state where one jug holds exactly the target amount (e.g. 2L).

Jug A · 4L
Jug B · 3L

It looks trivial with two jugs, but it's a real illustration of state-space search: each (amount-in-A, amount-in-B) pair is a "state," and each fill/empty/pour is an "edge" to a new state — exactly the same idea as the 8-puzzle, just small enough to draw the whole map.

🕸️ Every possible state, mapped

Unlike the 8-puzzle, the water jug's whole universe is tiny: only 5 × 4 = 20 possible (A, B) states. Here they all are — the ones actually reachable from (0,0) light up as our BFS search "discovers" them, and the target(s) pulse gold.

🧠 The algorithm, step by step

Click a step to expand it. Because the state space is so small, plain BFS (breadth-first search) already finds the shortest sequence of moves.

  • Represent a state as a pair (a, b) — litres currently in Jug A and Jug B.

    Start state: (0, 0).

  • Put the start state into a FIFO queue, and mark it visited.

    FIFO = first-in-first-out, so we always explore in "distance order" from the start.

  • Pop the front state. If a==target or b==target, stop — success!

    Reconstruct the path from the parent map.

  • Otherwise generate all 6 possible next states: fillA, fillB, emptyA, emptyB, pourA→B, pourB→A.

    Pouring math: pour amount = min(source amount, space left in destination).

  • For each next state not yet visited: mark visited, record its parent, and enqueue it.

    This guarantees we never re-explore a state and never loop forever.

  • Repeat steps 3–5 until target is found or the queue is empty.

    If BFS explores every reachable state without ever finding the target, the queue empties and we return "no solution" — that target amount simply can't be measured with these two jug sizes.

📦 Which data structures — and why

🚋

Queue (FIFO)

BFS explores level-by-level — all 1-move states, then all 2-move states, etc. A queue naturally preserves that order, which is exactly what guarantees the first time we see the target, it's reached in the fewest moves.

🕵️

Visited set

Stores every (a,b) pair we've already queued, so we don't loop between the same two or three states forever (e.g. fill then empty then fill again).

🧵

Parent map

Same trick as the 8-puzzle: remember which state led to which, so once we hit the target we can walk backwards and print the actual move sequence.

🔢

Tuple (the state)

(a, b) as a simple tuple — small, hashable, easy to put straight into a Python set or a Java HashSet<String>.

💻 Language: Python 🐍 — the complete solution

Why Python: collections.deque is an O(1) queue out of the box, and tuples slot straight into a set. (Java: LinkedList<> as your Queue<int[]> + a HashSet<String> — works, just chattier.)

STEP 2
def next_states(a, b, cap_a, cap_b):

The move-generator

Six buttons, six outcomes. Your job is just translating each button into arithmetic.

  • Fill A → (cap_a, b). Fill B → (a, cap_b).
  • Empty A → (0, b). Empty B → (a, 0).
  • Pour A→B — pour the smaller of "what A has" and "what room B has left": pour = min(a, cap_b - b).
  • Pour B→A — same idea, mirrored.
  • 💡 Note: some moves can return a state you're already in — e.g. "Fill A" when A is already full just gives back the same (a, b). Totally fine — Step 4's if state not in parent check quietly ignores it.
def next_states(a, b, cap_a, cap_b): moves = [] moves.append(((cap_a, b), "Fill A")) moves.append(((a, cap_b), "Fill B")) moves.append(((0, b), "Empty A")) moves.append(((a, 0), "Empty B")) pour = min(a, cap_b - b) moves.append(((a - pour, b + pour), "Pour A->B")) pour = min(b, cap_a - a) moves.append(((a + pour, b - pour), "Pour B->A")) return moves

STEP 3
def reconstruct(parent, state):

The path-rebuilder

Same trick as the 8-puzzle: walk the breadcrumbs back home, then flip the list around.

  • Every state's entry in parent stores (previous_state, move_label) — the start's entry is (None, None).
  • In plain English: starting from the goal state, repeatedly follow the parent links back to (0, 0), collecting each state and the move that led to it, until you hit the start.
  • Reverse the collected list before returning it — you built it goal-to-start, backwards!
def reconstruct(parent, state): path = [] while state is not None: prev_state, label = parent[state] path.append((state, label)) state = prev_state path.reverse() return path
⬇
STEP 4
def solve_jug(cap_a, cap_b, target):

Wire up the BFS search

The boss function — it just keeps asking Step 2 "what's next?" in the right order until it hears "target!"

  • Start a queue with (0,0), and a parent dict marking it as seen: {(0,0): (None, None)} — the tuple makes "this is the start" explicit rather than a bare None.
  • Loop: popleft() the front state. Goal test: a == target or b == target.
  • Otherwise call Step 2; for each state not already in parent, store parent[state] = (current_state, move_label) and enqueue it.
  • If the queue empties and the goal test never passed, that target amount is genuinely unreachable with these jug sizes — return None.
from collections import deque def solve_jug(cap_a, cap_b, target): start = (0, 0) q = deque([start]) parent = {start: (None, None)} while q: a, b = q.popleft() if a == target or b == target: return reconstruct(parent, (a, b)) for state, label in next_states(a, b, cap_a, cap_b): if state not in parent: parent[state] = ((a, b), label) q.append(state) return None # every reachable state checked -> target not measurable

from collections import deque

def next_states(a, b, cap_a, cap_b):
    moves = []
    moves.append(((cap_a, b), "Fill A"))
    moves.append(((a, cap_b), "Fill B"))
    moves.append(((0, b), "Empty A"))
    moves.append(((a, 0), "Empty B"))
    pour = min(a, cap_b - b)
    moves.append(((a - pour, b + pour), "Pour A->B"))
    pour = min(b, cap_a - a)
    moves.append(((a + pour, b - pour), "Pour B->A"))
    return moves

def reconstruct(parent, state):
    path = []
    while state is not None:
        prev_state, label = parent[state]
        path.append((state, label))
        state = prev_state
    path.reverse()
    return path

def solve_jug(cap_a, cap_b, target):
    start = (0, 0)
    q = deque([start])
    parent = {start: (None, None)}
    while q:
        a, b = q.popleft()
        if a == target or b == target:
            return reconstruct(parent, (a, b))
        for state, label in next_states(a, b, cap_a, cap_b):
            if state not in parent:
                parent[state] = ((a, b), label)
                q.append(state)
    return None  # every reachable state checked -> target not measurable

# --- try it ---
path = solve_jug(4, 3, 2)
for state, label in path:
    print(label, "->", state)
